## 1. 背景 — なぜ必要になったか

年輪候補 **8-2**「金の上昇には *ドル安 かつ BEが崩れないこと* の両方が要る」の**第二条件が、一度も実測されていない**。

代理指標を2回使い、2回とも失敗している：

| 代理 | 使用期間 | 結果 |
|---|---|---|
| `10s30s` | 8/4〜8/13 | 反例2件（8/5に金が週最大の上昇をした日に縮小、8/13に拡大したが金は無反応）→ **破棄済み** |
| **原油（WTI）** | 8/19 | 「原油85.15だからBE健在」と判定 → **同日公表のFOMC議事録が否定** |

8/19公表の7/28-29 FOMC議事録、マーケットデスク報告：

> 中東情勢の緊迫で原油価格は期間中に上昇して終わった。資産クラス横断では、**インフレ補償は原油高に対してほとんど動かず**、名目金利は主に政策金利見通しの上昇によって上昇した。近期のインフレ補償は6月FOMC後に大きく低下し、その後**原油の急騰にもかかわらず小幅にしか戻らなかった**。

つまり**原油とBEは連動していない**。原油をBEの代理に使うのは、10s30sを使ったのと同じ誤り。

これは `2026-06-27_belly-elevated_rex-curve-error.md` §8 の系列に入る。名前 → コメント → 窓 → 適用範囲 → 観測の取り方、と剥がしてきた層の、さらに一段下に「**測りたいものを測らず、相関があると思い込んだ別のものを測っていた**」があった。

**§8 (f) として追記してほしい。**

## 2. ★ これは TRADE_PAIRS への1行追加ではない

**データソースが違う。**

- 既存の `TRADE_PAIRS` / `CORE_TICKERS` は Yahoo Finance ティッカー（`^IRX` `^FVX` `^TNX` `^TYX`）
- `T5YIE` は **FRED のシリーズID**。Yahooには存在しない

`TRADE_PAIRS` にそのまま入れると、Yahooフェッチャが `T5YIE` をティッカーとして解決しようとして失敗する。**別フェッチ経路が要る。**

### 取得方法（APIキー不要）

```
https://fred.stlouisfed.org/graph/fredgraph.csv?id=T5YIE
```

認証なしでCSVが返る。形式は `DATE,T5YIE` の2列。

**注意点3つ:**

1. **欠損値は `.`（ピリオド）で返る**。祝日・データ未確定日に出る。`float()` が例外を投げるので明示的に処理すること
2. **非営業日の行は存在しない**。位置指定（`iloc[-7]`）ではなく**日付基準**で窓を取ること（`prev_1w` の実装と同じ方針）
3. **公表ラグがある**。当日分は当日中には出ない（通常は翌営業日）

## 3. ★ 公表ラグの扱い — ここが最重要

FREDのBEは、Yahooの価格データより**1日古い可能性が常にある**。

これを黙って同じスナップショットに並べると、**今週7回繰り返した「測定窓の不一致」を機械に焼き付けることになる**。

### 必須要件

**BEの値には必ず `as_of` 日付を添えて出力する。**

```yaml
inflation_compensation:
  # FRED（Yahooとは別フィード）。公表ラグがあるため as_of を必ず確認すること。
  # 他ブロックの価格は当日、ここは as_of の日付。同日として比較しないこと。
  us5y_be_as_of: 2026-08-19        # ★ 必須
  us5y_be_pct: 2.34                 # 水準は%表記（bpではない）
  change_5ybe_bp_1w: -3.0           # 週次Δ（bp）
  change_5ybe_bp_30d: 8.0           # 30日Δ（bp）
  direction_5ybe_1w: narrowing      # 週次Δの符号のみ。閾値は未設定＝判定はしない
```

`as_of` が他ブロックの日付と一致しない場合、**それは異常ではなく正常**。人間とLLMが読んだときに気づけることが要件。

## 4. 実装内容

### 4-1. `configs/settings.py`

Yahooの辞書とは**別の辞書**として定義する。同じ辞書に混ぜない。

```python
# FRED シリーズ（Yahooとは別ソース・別フェッチ経路・公表ラグあり）
# 命名の原則は本ファイル冒頭のとおり。代用品には本物の名前を付けない。
FRED_SERIES: Dict[str, str] = {
    "US5YBE":   "T5YIE",    # 5年ブレークイーブン＝近期インフレ補償
    "US5Y5YBE": "T5YIFR",   # 5年5年先フォワード＝長期インフレ期待アンカー
}
```

**T5YIFR も入れてほしい理由：**

議事録が言っているのは「**近期の**インフレ補償」が動かなかったということ。近期（5Y BE）はエネルギー価格の影響を受けやすく、5y5yフォワードはそれを剥いだアンカー。

**2つの差が診断になる**：

- **5Y BEだけ動いて5y5yが動かない** → 市場は原油の影響を一時的と見ている
- **両方動く** → インフレ期待そのものが動いた

8-2が問いたいのは後者なので、**1本だけだと判別できない**。追加コストは1行。

### 4-2. `src/market.py`

FRED取得関数を追加。既存のYahoo取得関数とは分離する。

- 欠損値 `.` のスキップ
- 日付基準での `prev_1w` / `prev_30d` 抽出（既存の `pair_snapshots` と同方針）
- 取得失敗時は `None` を返し、**例外を握り潰さない**（§5参照）

### 4-3. `src/regime.py`

`_inflation_compensation()` を新設。出力は §3 のとおり。

## 5. ★ やってはいけないこと

### 5-1. レジームラベル・複合スコアに入れない

`_yields_regime()` にも、他のどの合成指標にも**混ぜない**。US30Y を入れなかったのと同じ理由。

サンプルがゼロの指標に判定させると、判定が実測より先に固まる。**8-2で2回やった失敗そのもの。**

### 5-2. 閾値を置かない

`direction_5ybe_1w` は**符号のみ**。「BEが崩れた」の水準を今決めない。

理由は10s30sと同じで、**サンプルがない**。8〜12週ためてから検討する。

### 5-3. 原油との相関を自動計算しない

やりたくなるが、まだやらない。**議事録の観測（原油とBEが連動しない）は1期間分の1事例**であって、僕らはまだ自分で確かめていない。相関を機械が出すと、それが検証済みの事実として扱われる。

まず生の系列を数週間ためる。それから。

### 5-4. ★ 例外を握り潰さない

8/9の改名時、`rex_chat.py` の try/except が `_curve_2s10s is not defined` を握って、**`--trade` は完走するのに curve ブロックだけ欠落する**という経路が見つかった。

`settings.py` 冒頭の原則「欠損は気づかれるが間違った値は気づかれない」は、**欠損が欠損として見えるときにしか成り立たない**。

FRED取得は外部HTTPなので、Yahooより失敗しやすい。**必ず区別できる形で出す：**

```yaml
inflation_compensation: null   # ERROR: <例外クラス名>（データ欠損ではなく取得失敗）
```

他ブロック（intervention / relative_strength など）が同じ形なら、同じ処理を回してほしい。

## 6. 初回サニティチェック（目視必須）

| 項目 | 期待 |
|---|---|
| `T5YIE` の水準 | **2〜3程度**（%表記）。235 や 0.023 なら単位の取り違え |
| `T5YIFR` の水準 | 同上。通常 T5YIE と1%以内の差 |
| `as_of` | 実行日または**その1〜2営業日前**。1週間以上古ければ取得ロジックの不具合 |
| 欠損処理 | 直近に祝日を含む期間で `.` が来ても落ちないこと |
| Δの符号 | 手計算1点と突き合わせる |
