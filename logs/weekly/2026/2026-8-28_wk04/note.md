### ★★ NaN が「欠損」ではなく【誤ったラベル】に化けていた

| 出力 | 値 | 実態 |
|---|---|---|
| `regime.equities` | **flat** | `_equities_regime()` は `is None` のみ unknown を返し、**NaN は比較が全て False で最後の `return "flat"` に落ちる** |
| `relative_strength.verdict` | **mixed** | 同じく **NaN が else 分岐に落ちた産物**（`us100_30d` / `nominal` / `fx_adj` はいずれも nan） |

→ ★ **`settings.py` 冒頭の「欠損は気づかれるが、間違った値は気づかれない」の実例。**
**本週は `equities=flat` と `verdict=mixed` を読まない。**

★★ **【Boss訂正 2026-08-29】これは上の2関数だけの話ではない。** NaN は比較が全部 False になるので、
**末尾に無条件 `return` を持つ判定関数はすべて同じ穴を持つ**。今週たまたま露見したのがこの2つだっただけ。
→ ★ **監査範囲＝「終端フォールバックを持つ判定関数の悉皆」**、**是正＝「各判定関数に NaN を食わせて `unknown` を返すテストを1本書く」**。
**関数ごとに if を足すのではなく、テストが穴の一覧を出す形にする。** → **修正可否は関所で確認**。
