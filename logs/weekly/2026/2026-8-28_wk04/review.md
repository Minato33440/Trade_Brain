### ★★ NaN が「欠損」ではなく【誤ったラベル】に化けている（要修正の候補）

| 出力 | 値 | 実態 |
|---|---|---|
| `regime.equities` | **flat** | ★**NaN の産物**。`_equities_regime()` は `ch_us100 is None` のみ unknown を返し、**NaN は比較が全て False で最後の `return "flat"` に落ちる** |

→ ★**`settings.py` 冒頭の「欠損は気づかれるが、間違った値は気づかれない」の実例。**
**本週の `equities=flat` と `verdict=mixed` は読まないこと。**

★★ **【Boss訂正 2026-08-29】これは上の2関数だけの問題ではない。**
NaN は比較演算がすべて False になるため、**「分岐を全部すり抜けて最後の `return` に落ちる」構造を持つ判定関数はすべて同じ穴を持つ**。
今週たまたま露見したのが `_equities_regime()` と `_relative_strength()` だっただけで、**個別に直すのは対症療法**。
→ ★**監査範囲は「末尾に無条件 `return` を持つ判定関数の全て」**（`src/regime.py` の `_*_regime()` 系・
`_curve_spreads()` / `_inflation_compensation()` / `_relative_strength()` / `_intervention_watch()` 等を悉皆で洗う）。
→ ★**是正は「各判定関数に NaN を食わせて `unknown` が返ることを確認するテストを1本書く」**。
関数ごとに if を足すのではなく、**テストが穴の一覧を出す形にする**。→ **関所で実施可否を確認**。
